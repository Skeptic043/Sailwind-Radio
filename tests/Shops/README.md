# Shop checks

Run `dotnet run --project tests/Shops/ShopChecks.csproj -c Release` for production reservation, purchase callbacks, display lifecycle and restock rules. The harness executes the real save store, global arbiter, reservation helper, service callbacks and restock clock. Unity APIs, stand construction and the world-service boundary are explicit doubles. It covers capacity and schema failures before charging, native identity collisions, failed registration, duplicate purchases, original vendor linkage, direct pricing-parent repair, the unsold boat-entry guard, held-stock return, partial initial stock followed by restock, warning deduplication, world-load cleanup, day/night stock and preservation of purchased items. The destruction double recursively destroys children and components, and the native sale double detaches the purchased object before registration.

Run `dotnet run --project tests/Shops/Placement/PlacementChecks.csproj -c Release` for the production fixed stand layout and placement logic against synthetic physics. It covers authored capital selection, metric offsets independent of shop scale, nine ground-support checks, full-display and customer-approach clearance, dynamic item blockers, level support, deterministic positions, restock filtering, all seven device envelopes, pairwise device separation, ground woofer placement and approximate standing pickup reach. No grid search remains.

Run `tests/Shops/Run-NativeContractChecks.ps1` against the independently installed game for five production compatibility checks on Unity Mono. It reads the actual native method bodies and verifies observed ownership-before-charge order, the pricing multiplier and registration members, and exact private `EnterBoat(Collider)` and `GetPrice(ShipItem)` signatures. It does not call game methods or change game files. Linear instruction order is not a general proof of future control flow.

Runtime stock uses a Radio-owned merchant through native `AddToShop` after final placement. It keeps native purchase UI, currency conversion, reputation discounts and logs. The owned NPC retains a short trigger for nearby held-item resale and disables its broad child trigger. A failed registration aborts before native charging and removes provisional ownership. If an unrelated native callback fails after successful registration, the registered item is retained. That exceptional native/UI path remains distinct from ordinary purchase success.

These checks do not establish live Unity collision accuracy, display appearance, pickup UI, resale or save/reload acceptance. Actual installed scene geometry was inspected separately. Runtime placement reports overlap while still showing the Radio stand for player review. A purchased device left on the temporary shop stand should be included in live save/reload testing.
