# Shop checks

Run `dotnet run --project tests/Shops/ShopChecks.csproj -c Release` for production ownership binding, shop callbacks, save store, global arbiter, display lifecycle and restock rules. `src/Physical/RadioWorldService.Ownership.cs` is the same partial world-service implementation compiled into the mod. Unity objects, native method bodies, controller visuals and the remaining world-service dependencies are explicit doubles. Native registration in the double allocates a positive ID when zero and retains its registered flag after removal from the registry. The harness does not emulate the full installed Harmony patch order or execute the production world's complete save/load lifecycle.

All four device kinds exercise ordinary merchant purchase and the observed replacement sequence that calls `ShipItem.Sell` directly before charging. Cases cover native allocation without Radio registration callbacks, repeated binding, first interaction, immediate capture/save of never-activated devices, interrupted registration without Radio cleanup, read-only documents without a sale veto, fresh acquisition while loading, loaded devices kept on the restoration path, record-kind mismatch, canonical settings and migrated donor devices. Extension-data roundtrips do not establish native save/reload acceptance. Existing display, stock protection, pricing-parent, merchant linkage, restock, cleanup and day/night cases remain covered.

Run `dotnet run --project tests/Shops/Placement/PlacementChecks.csproj -c Release` for the production fixed stand layout and placement logic against synthetic physics. It covers authored capital selection, metric offsets independent of shop scale, nine ground-support checks, full-display and customer-approach clearance, dynamic item blockers, level support, deterministic positions, restock filtering, all seven device envelopes, pairwise device separation, ground woofer placement and approximate standing pickup reach. No grid search remains.

Run `tests/Shops/Run-NativeContractChecks.ps1` against the independently installed game for native signature checks on Unity Mono. It checks the pricing multiplier and registration member, and exact private `EnterBoat(Collider)` and `GetPrice(ShipItem)` signatures. It does not call game methods or change game files. Purchase ordering is inspected separately and is no longer an IL gate in production.

After building, run `tests/Shops/Run-PurchasePatchChecks.ps1 -LoaderPath <installed-BepInEx-core>` for actual Harmony wrapper construction against the compiled Radio and installed native assemblies. It validates the native capture prefix and prefab load prefix/postfix, checks patch records, then explicitly removes its own patches. Input hashes and results stay under ignored `tests/Shops/obj/purchase-patches`. No game method or Radio service is invoked. The standalone Unity editor Mono host does not establish in-game callback execution or ordering with other mods.

Runtime stock uses a Radio-owned merchant through native `AddToShop` after final placement. Acquisition follows the native `Sell`, `RegisterToSave` and `OnBuy` lifecycle. Sailwind allocates instance IDs. Radio binds its extension state after native ownership through pending-controller updates, interaction and native capture. Controls unlock when ownership and matching canonical Radio state are valid. Unheld display stock waits inactive when shop readiness is unavailable, while held stock and native return movement stay active during transient readiness loss. Native stock spawning remains separate from this ownership change.

Radio does not intercept sales or native registration, reserve IDs, remove native IDs or roll back purchases. A partly sold but unregistered object stays restricted and unpromoted. Read-only Radio data remains preserved. Fresh acquisition can create initial state after ownership, while loaded devices retain the existing missing-record and duplicate-restoration rules. The fixed prefab-slot check and basic record-kind validation remain.

These checks do not establish live Unity collision accuracy, display appearance, pickup UI, resale or save/reload acceptance. Actual installed scene geometry was inspected separately. Runtime placement shows the Radio stand even where nearby scenery overlaps it, and reports only stalls that cannot be set up. A purchased device left on the shop stand should be included in live save/reload testing.
