# Shop checks

Run `dotnet run --project tests/Shops/ShopChecks.csproj -c Release` for the production native-registration hooks, shop callbacks, save store, global arbiter, display lifecycle and restock rules. `RadioWorldPurchases.cs` is the same partial world-service implementation compiled into the mod. Unity objects, native method bodies, controller visuals and the remaining world-service dependencies are explicit doubles. The harness manually dispatches patch callbacks and does not emulate the full installed Harmony patch order.

All four device kinds exercise ordinary merchant purchase and the observed replacement sequence that calls `ShipItem.Sell` directly before charging. Cases cover skipped or interrupted native calls, exceptions after successful registration, duplicate and reentrant callbacks, capacity/schema/state failures, ID collisions and cleanup of the original provisional identity. Starting-supply registration deferral, preserved records, bounded recovery of valid old marked stock, and extension-data roundtrips are checked separately. A roundtrip is not native save/reload acceptance. Existing display, stock protection, pricing-parent, merchant linkage, restock, cleanup and day/night cases remain covered.

Run `dotnet run --project tests/Shops/Placement/PlacementChecks.csproj -c Release` for the production fixed stand layout and placement logic against synthetic physics. It covers authored capital selection, metric offsets independent of shop scale, nine ground-support checks, full-display and customer-approach clearance, dynamic item blockers, level support, deterministic positions, restock filtering, all seven device envelopes, pairwise device separation, ground woofer placement and approximate standing pickup reach. No grid search remains.

Run `tests/Shops/Run-NativeContractChecks.ps1` against the independently installed game for native compatibility checks on Unity Mono. It reads the actual native method bodies and checks ownership-before-registration order, the pricing multiplier and registration members, and exact private `EnterBoat(Collider)` and `GetPrice(ShipItem)` signatures. It does not call game methods or change game files. Linear instruction order is not a general proof of future control flow.

After building, run `tests/Shops/Run-PurchasePatchChecks.ps1 -LoaderPath <installed-BepInEx-core>` for actual Harmony wrapper construction against the compiled Radio and installed native assemblies. It validates the registration prefix/postfix/finalizer and sale prefix/finalizer state signatures, checks patch records, then explicitly removes its own patches. Input hashes and results stay under ignored `tests/Shops/obj/purchase-patches`. No game method or Radio service is invoked. The standalone Unity editor Mono host does not establish in-game callback execution or ordering with other mods.

Runtime stock uses a Radio-owned merchant through native `AddToShop` after final placement. Acquisition follows the native `Sell`, `RegisterToSave` and `OnBuy` lifecycle. Radio creates its extension state through the same registration hook used for direct spawning and starting supplies. Controls unlock only when native ownership and the matching Radio record are valid. If a later callback fails after successful registration, the acquired device is retained.

Failed registration preserves the original error and removes only that attempt's unowned provisional state. A partly sold but unregistered object stays restricted and unpromoted, with no promise of automatic retry or save recovery. The inspected ordinary merchant and EconomyOverhaul caller charge after `Sell`, so an escaping error prevents their following subtraction. Radio does not own or roll back another mod's payment and cannot guarantee its ordering. Unsold display stock remains restricted, and recovery never invents a missing per-device record or resolves an ambiguous ID.

These checks do not establish live Unity collision accuracy, display appearance, pickup UI, resale or save/reload acceptance. Actual installed scene geometry was inspected separately. Runtime placement shows the Radio stand even where nearby scenery overlaps it, and reports only stalls that cannot be set up. A purchased device left on the shop stand should be included in live save/reload testing.
